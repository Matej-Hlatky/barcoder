# UX Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nine scoped UX fixes — an icon theme switch, a stable scrollbar gutter, a one-row download strip without WEBP, non-negative number affordances, a custom select caret, WCAG-compliant control borders, right-aligned numeric fields, a favicon, and an interface that does not select as text.

**Architecture:** Nearly all of this is CSS. Three design tokens (`--control-border`, `--caret`) carry the visual changes through the existing three-block theme cascade, so no colour is defined only inside a media query. The only new module is `src/icons.js`, holding Phosphor SVG markup as strings — inlined rather than depended on, because the project keeps exactly one runtime dependency. `src/ui.js` gains a `parse()` helper (SVG needs the HTML parser, not `createElement`) and a `syncTheme()` export so the switch's `aria-checked` cannot drift from the applied theme.

**Tech Stack:** Vanilla ES modules, esbuild, vitest (+ jsdom), Playwright. Phosphor Icons (regular weight, MIT) as inlined markup.

**Spec:** `docs/superpowers/specs/2026-08-25-barcoder-design.md`

This is bounded work, so the approved design lives in this plan rather than in a
new spec file. Four items knowingly deviate from the spec above; Task 7 records
those deviations in the spec itself, and no task may silently contradict it.

## Global Constraints

- **Never import bwip-js as a default.** No task here touches `src/encoder.js`; if that changes, import symbols by name (see `CLAUDE.md`).
- **Theme colours are defined in all three cascade blocks** — `:root`, then `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) }`, then `:root[data-theme='dark']`. Never define a colour only inside the media block. Task 1 adds a test that enforces this.
- **Tap targets are at least 48px.** The shared `button, select, input` rule sets `min-height: 48px`; keep it.
- **Comments explain why, not what.** The codebase carries about twenty comments. Add at most the two this plan specifies.
- **Bundle ceilings:** entry ≤ 12 KB gzip, encoder ≤ 115 KB gzip, enforced by `npm run build`. Current entry is **3.2 KB** and the encoder **100.4 KB**, so the two inlined icons (~1.2 KB raw) have ample headroom. The build is still the gate.
- **`history.replaceState`, never `pushState`.** No task changes URL handling.
- **Defaults are absent from the URL.** No task changes `toQuery`/`fromQuery`.
- **Exact colour values** (computed against WCAG 1.4.11's 3:1 floor for control boundaries):
  - Light `--control-border: #84848d` — 3.37:1 vs `--surface #f4f4f5`, 3.71:1 vs `--bg #ffffff`
  - Dark `--control-border: #71717a` — 3.52:1 vs `--surface #1c1c1f`, 3.96:1 vs `--bg #0f0f10`
  - Existing `--border` (`#e4e4e7` / `#2e2e33`) stays as-is for panel and preview frames — it measures 1.15:1 and 1.26:1, which is why controls need their own token.

```js
import { describe, it, expect } from 'vitest';
import { readFileSync } from 'node:fs';

const css = readFileSync('src/styles.css', 'utf8');

const LIGHT = ':root';
const DARK_MEDIA = ":root:not([data-theme='light'])";
const DARK_ATTR = ":root[data-theme='dark']";

function tokensOf(selector) {
  const escaped = selector.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
  const match = css.match(new RegExp(`${escaped}\\s*\\{([^}]*)\\}`));
  if (!match) throw new Error(`no rule for ${selector}`);
  return Object.fromEntries(
    [...match[1].matchAll(/(--[\w-]+):\s*([^;]+);/g)].map(([, k, v]) => [k, v.trim()])
  );
}

const channel = (c) => ((c /= 255) <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4);

function luminance(hex) {
  const n = parseInt(hex.slice(1), 16);
  return 0.2126 * channel((n >> 16) & 255) + 0.7152 * channel((n >> 8) & 255) + 0.0722 * channel(n & 255);
}

function contrast(a, b) {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
}

describe('theme cascade', () => {
  it('defines the same tokens in both dark blocks', () => {
    expect(tokensOf(DARK_MEDIA)).toEqual(tokensOf(DARK_ATTR));
  });

  it('defines no token only inside the media block', () => {
    const light = Object.keys(tokensOf(LIGHT));
    for (const key of Object.keys(tokensOf(DARK_MEDIA))) expect(light).toContain(key);
  });
});

describe('control border contrast', () => {
  for (const [name, selector] of [['light', LIGHT], ['dark', DARK_MEDIA]]) {
    it(`clears 3:1 against both backgrounds in ${name}`, () => {
      const t = tokensOf(selector);
      expect(contrast(t['--control-border'], t['--surface'])).toBeGreaterThanOrEqual(3);
      expect(contrast(t['--control-border'], t['--bg'])).toBeGreaterThanOrEqual(3);
    });
  }
});

describe('layout stability', () => {
  it('reserves the scrollbar gutter', () => {
    expect(css).toMatch(/html\s*\{[^}]*scrollbar-gutter:\s*stable/);
  });
});
```

### Task 7: No text selection outside inputs

Added to the plan mid-execution at the user's request: the interface should not
be selectable, inputs excepted. On a touch device a long-press on a label or a
button currently starts a text selection instead of feeling like a control, and
a drag across the header selects the heading.

Note the deliberate cost: `.error` messages and the barcode's own human-readable
text stop being selectable too, so a user cannot copy an error string. The text
input remains the place text is copied from, which is where the payload lives.

`user-select` inherits, so a single declaration on `body` covers the whole tree
and inputs need an explicit override. The `-webkit-` prefix is not optional
here: iOS Safari needed it until 17.4, and this is a mobile-first app.
